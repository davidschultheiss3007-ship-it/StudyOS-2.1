## Pakete installieren und laden

- Pakete liefern einen **erweiterten Funktions- und Befehlsumfang** – um leichter mit R zu arbeiten (**mosaic**) oder um spezifische Analysen und Anwendungen bereitzustellen (**dplyr**).
- Benötigt wird (erstmal) **nur ein Paket: mosaic**. Darin sind viele Pakete integriert (z. B. dplyr) – sie müssen nicht extra installiert und geladen werden.
- **Standard-R-Befehle** können immer angewandt werden. Für **Paketbefehle** müssen Pakete **immer(!) geladen** werden.

<Columns count={2}>
<Card title="Installieren · einmal" tone="accent">

```r
install.packages("mosaic", dependencies = TRUE)
```

In der R-Console eingeben, `Enter` bzw. `Return`. Internetverbindung nötig; abhängige Zusatzpakete werden mitinstalliert.

</Card>
<Card title="Laden · in jeder Sitzung" tone="purple">

```r
library(mosaic)
```

Erst danach kann R auf die hinterlegten Befehle des Pakets zugreifen.

</Card>
</Columns>

<Callout type="tip" title="Nur Hinweise, keine Fehler">
Nach `library(mosaic)` erscheinen Meldungen wie *„Registered S3 method overwritten by 'mosaic'“* oder *„Die folgenden Objekte sind maskiert von ‘package:dplyr’: count, do, tally“*. Das sind **nur Hinweise, keine Fehler!**
</Callout>

## Der mosaic-Grundbefehl

mosaic wurde für R-Studierende entwickelt: Es gibt **einen einzigen (!) Code mit wenigen Variationen**.

```r
Befehl_was_mag_ich_machen( abhVar ~ unabhVar | Bedingung, data = meineDaten)
```

Eine **Bedingung** ermöglicht z. B. eine **Gruppierung**:

```r
analysiere(y        # abhängige Variable
           ~ x      # unabhängige Variable(n)
           | z,     # ggf. bedingende (gruppierende) Variable(n)
           Optionen, # ggf. weitere Optionen
           data = meine_daten)  # Datensatz
```

<Callout type="info" title="Tastatur unter macOS">
Tilde `~`: **opt + n** · senkrechter Strich `|`: **opt + 7**
</Callout>

Das sind **Formel und Daten** – `mein.y ~ mein.x, data = meine.daten`.

### Import: Daten einlesen

Liegen die Dateien z. B. im Verzeichnis `C:/Ordner/weitere Unterordner/Vorlesung`, muss R wissen, **wo sich die Dateien befinden**. Das **Arbeitsverzeichnis** wird festgelegt mit:

```r
setwd("/Users/ihrname/Ordner/Unterordner…/Vorlesung")   # Mac
setwd("C:/Ordner/Unterordner…/Vorlesung")               # Windows
getwd()                                                  # aktuelles Arbeitsverzeichnis anzeigen
```

<Callout type="warn" title="Wichtig für den Pfad">
Der Pfad muss mit **/ (Slash)** geschrieben werden und **in Anführungszeichen** stehen. Die Folien zeigen typografische Anführungszeichen („ “); in R-Code sind **gerade Anführungszeichen** (`"`) nötig.
</Callout>

**Einlesen von Dateien:** Mit `data <-` wird der Inhalt der Datei der Tabelle `data` zugeordnet. Die Daten können nun aufgerufen, bearbeitet und analysiert werden.

<Columns count={2}>
<Card title="read.csv()" tone="accent">

```r
data <- read.csv("meineDatentabelle.csv")
```

Liest Daten mit **Dezimalpunkt** ein (englisches / amerikanisches Zahlenformat).

</Card>
<Card title="read.csv2()" tone="purple">

```r
data <- read.csv2("meineDatentabelle.csv")
```

Liest Daten mit **Dezimalkomma** ein (deutschsprachiges Zahlenformat).

</Callout>

### Tidy: Daten bereinigen

**tidy data** bedeutet, dass die Daten nach einer anerkannten, gebräuchlichen und einheitlichen Form auf- bzw. vorbereitet sind – der **einheitlichen Form eines Datensatzes (Normalform)**.

- **Jede Zeile** gehört **einer Beobachtung**, die meist durch eine Art „ID“ zuordenbar ist.
- Entsprechen die Daten nicht dieser Form, **sollte die Datentabelle in diese Form gebracht werden**. Sind die Daten tidy, werden sie im nächsten Schritt transformiert.

### Transform, Visualize, Model, Communicate

<Columns count={2}>
<Card title="Transform: Daten transformieren" tone="accent">

- **Einschränken** auf die Daten von Interesse: alle Beobachtungen einer Stadt; Aktienkurse in einem bestimmten Zeitraum.
- **Neue Variablen** erzeugen: Tempo aus Distanz und Zeit; **Renditen** aus aktuellem Aktienkurs und dem der Vorperiode.

- Ein Modell ist ein **Werkzeug zur Hypothesenprüfung**; die Hypothese wird nach der Analyse angenommen oder verworfen.

</Card>
